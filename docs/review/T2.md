**沒有 High。** 有 5 個 Medium，3 個和 Esc 中斷子程序有關（V1～V3）、1 個和「篩選掉但仍然勾選著的列」被刪除有關（V4）、1 個是 design 裡關於殘留 session 的說法不正確（V5）。

# Review：openspec change tui-batch-actions（T2 互動模式的批次動作）

2026-10-03，review。對象：`openspec/changes/tui-batch-actions/` 的 proposal.md、design.md、tasks.md、specs/interactive-mode/spec.md（`2b9854e`），對照 `command-batch-actions` 的 specs（session-sync、batch-commands）。只提意見，沒有改任何東西。依照指示，沒有跑整合測試、沒有碰 Drive、沒有讀任何真實的 Session，也沒有執行不帶參數的 `agora`。

## 結論

「互動模式的每個動作都在子程序裡跑同一個 `agora` 指令」這個方向是對的：它順便解決了 cache.md 的 K3（`redirect_stdout` 會換掉整個程式的 stdout），也讓中斷變得可行。和 command-batch-actions 的 specs 沒有直接的矛盾，只有幾個需要說清楚的地方（V6）。測試**寫得出來**，但 Esc 送出 SIGINT 這一段，至少要有一個測試用**真的子程序**來跑（V7）。

| # | 嚴重度 | 一句話 |
|---|---|---|
| V1 | Medium | 子程序沒有規定 `stdin=DEVNULL`。就算 `start_new_session=True`，它還是會繼承 Textual 正在用的終端機 fd 0；只要指令或它叫起來的 agent 讀了 stdin，就會**搶走使用者的按鍵**，或者卡在那裡等輸入 |

## Esc 中斷子程序的風險

design：`[sys.executable, "-m", "agora.cli", …]`，stdout 和 stderr 合併之後逐行讀，`start_new_session=True`，Esc 時對整個 process group 送 SIGINT。

**做得對的地方**
- `start_new_session=True`：子程序會成為新的 session leader，沒有 controlling terminal，所以終端機的 Ctrl-C 不會誤送給它；中斷完全由 Textual 控制 ✅。
- 指令模式的 `cli.main` 會接住 `KeyboardInterrupt`，印一行說明，然後回傳 130 ✅。
- 指令裡用 `subprocess.run(...)` 啟動的 agent（寫要約的 `opencode run`、`claude -p`）和 rclone，都在**同一個** process group 裡，所以也會收到 SIGINT ✅。而且 Python 的 `subprocess.run` 在等待期間遇到例外時，會先 `kill()` 直接的子程序再往外丟，所以就算 agent 不理 SIGINT，直接的那一層也會被停掉。
- 各種寫入被中斷時，已經有既有的機制收拾：outbox 的換入（R6）、push 的「先 raw、後 session.md」（S1）、rclone 下載中斷留下的 `.partial` 不會被 push 上去（R7）、merge 每寫好一節就先存起來（R4）✅。

**要補的地方**

1. **V1：`stdin=subprocess.DEVNULL`**。`start_new_session` 只是讓子程序脫離 controlling terminal，**它繼承下來的 fd 0 仍然是同一個 tty**。Textual 是在 raw mode 下讀這個 tty 的，子程序（或者它啟動的 agent／rclone）只要讀了一次 stdin，就會和 Textual 搶按鍵。design 要明寫 `stdin=DEVNULL`，另外建議加上 `env={**os.environ, "PYTHONUNBUFFERED": "1"}`，否則子程序的 stdout（例如 agora id）會被區塊緩衝，要等到結束才一次讀到（stderr 在 Python 3.9 之後是行緩衝，所以進度不受影響）。
2. **V2：升級的步驟**。建議：Esc → `os.killpg(pgid, SIGINT)`；3 秒內沒有結束 → `SIGTERM`；再 3 秒 → `SIGKILL`。等待視窗要顯示「中斷中…」，並且接住 `ProcessLookupError`（子程序剛好已經結束了）。被 SIGKILL 的 agora 子程序沒有機會印出「重跑會接著做」，所以這句說明要由 TUI 自己顯示。
3. **V3**：因為 Esc 會讓「中斷在任何一行」變成**常態**，T1-sec1 的 S1-4（`delete_session` 要把「資料夾不存在」當成已經刪掉）應該在 T2 之前修好；在 spec 的「中斷後畫面 MUST 回到清單並說明『重跑同一個動作會接著做』」底下，也要加上它依賴 S1-4。
4. **V5**：design 的那一條 Risk 要改寫，說明正確的情況：被中斷的 summarize 可能會在 `<state>/summarize/` 留下一個 opencode session；那個專案的 session 不會出現在未匯入頁上（T5），**但不會被自動刪掉**。如果要補刪，就要用 Z2 那時建議的方式：在 `<state>/summarize/` 這個 agora 專用的專案裡，`opencode session list` 再依 id 一個一個刪（那裡只會有 agora 自己建的 session）。
5. **孫程序**：如果 agent 自己又啟動了**新的** session（例如某些 server 會 `setsid`），送給 process group 的訊號就碰不到它。這是已知的限制，在 design 寫一句就好。

## V4（Medium）：被篩選掉的勾選列

- spec 的「全選切換」寫明了「篩選掉的列的勾選狀態 MUST NOT 被改變」，所以「之前勾過、後來被篩選掉」的列，會一直保持勾選。
- 「動作作用在勾選的列」沒有寫，這些看不到的列算不算。如果算，那麼使用者 `/` 篩選 → `a` 全選 → `d` 刪除時，刪掉的會是「看得到的**加上**之前勾過但看不到的」，**比畫面上看到的還多**。
- **建議**（寫進 spec）：動作**只**作用在「勾選、而且目前看得到」的列；或者，如果要包含看不到的，確認視窗就一定要列出**全部**會被處理的 id，並且寫出「其中 N 個目前被篩選掉了」。delete、push 的 `--not-exist-upload`、pull 的 `--not-exist-delete` 都屬於比較危險的動作，建議採用前者。單元測試：篩選之後按 `d`，只送出看得到的那幾個。

## 和 command-batch-actions 的對照（V6）

| 項目 | 狀況 | 建議 |
|---|---|---|
| 未匯入頁的 import／pull | 未匯入頁會列出 opencode 和 claude 的 session；指令模式的 import 一次只能指定一個 `--agent`（Q12）。tasks 1.2 已經寫了「同一個 agent 的列合成一個指令」 | spec 要寫明：會依序跑兩個指令，進度條會**分成兩段**（例如「opencode 1/3」→「claude 1/2」），或者合成同一條（總數是 5）；Esc 會連後面那個指令一起取消 |
| merge 來源的順序 | 指令模式的 merge 會依照給的順序排出各節，但 spec 沒有寫 TUI 是用什麼順序交給它的 | 寫明是「勾選的先後順序」，或者「清單上由上而下的順序」，二選一 |
| exit code | 子程序的回傳值可能是 0、1（做不到）、2（錯誤）、3（存進 outbox）、130（中斷） | spec 寫明每一種在畫面上的說法，例如 3 →「已存在本機，之後的指令會自動上傳」，130 →「已中斷，重跑同一個動作會接著做」 |
| 「雲端」欄 | 讀索引裡的標記和 outbox ✅，和 session-sync 的三種狀態一致。標記只會在**完整列檔成功**的同步之後更新，所以在 TUI 裡做完一個動作、只重讀本機索引時，這一欄可能是舊的 | spec 寫明「雲端欄反映的是上一次同步的結果」，pull／push 之後的那一次重讀，也要包含 pull 或 push 自己知道的結果 |
| 接續或改標頭一個 ✗ 的列 | 指令模式會拒絕（session-sync「其他指令遇到雲端沒有的 Session」）✅；TUI 的 continue／edit 是用 `suspend()` 在**本程序**裡跑 `cli.main`，拒絕的訊息會印在 suspend 之後的終端機上 | 可以接受；或者 TUI 在 suspend **之前**先看「雲端」欄，直接在畫面上顯示拒絕訊息和兩個選擇，連 suspend 都不必（這樣也比較符合 spec「畫面顯示」的寫法） |
| 做完之後的勾選 | 沒有寫 | 建議：成功的就取消勾選，失敗的保留勾選，這樣「重跑」只要再按一次同樣的鍵 |

## V8（Low）：`k/N` 的解析

「從輸出裡最後一個 `k/N` 讀」：標題（「第 1/3 步」）、日期（`10/02`）、路徑裡都可能有 `數字/數字`。建議只認 `^\[agora\] \S+ (\d+)/(\d+)` 這種格式（也就是指令模式 `_progress` 的格式），並且要求 `1 ≤ k ≤ N`，其他的一律忽略。
