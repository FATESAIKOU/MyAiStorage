## T1（Medium）：client 檔不是 UTF-8 時，首次設定當掉，例外訊息裡看得到 secret

`read_client` 只接住 `OSError`，可是 `Path.read_text(encoding="utf-8")` 遇到不是 UTF-8 的檔案，丟的是 `UnicodeDecodeError`（屬於 `ValueError`）。它一路往上，變成 Textual worker 的 `WorkerFailed`，整個 app 結束。

實測（照現有的 `_first_run` 開首次設定，選第二項，打路徑）：

| 給的檔案 | 結果 |
|---|---|
| 一張圖片（打錯路徑） | app 結束：`WorkerFailed: Worker raised exception: UnicodeDecodeError('utf-8', b'\x89PNG…', 0, 1, 'invalid start byte')` |
| **Google 的 client JSON 另存成 UTF-16**（例如用 Windows 記事本的「Unicode」存過） | app 結束；例外訊息有 663 個字，**secret 讀得出來**：每個字母中間夾一個 `\x00`，`G\x00O\x00C\x00S\x00P\x00X\x00-\x00…` |

原因：`UnicodeDecodeError` 的 repr 會帶上**整個**讀到的 bytes。而且 Textual 當掉時印 traceback，用的是 `show_locals=True`（`textual/app.py:3291`），所以這段文字會留在終端機上（和捲動紀錄裡）。

另外兩種 JSON 形狀也會當掉：`"installed"` 是字串或 list 的時候，`block.get` 在 `try` 外面，丟出 `AttributeError`。我照 Textual 的參數（`show_locals=True, locals_max_length=5`）把 traceback 畫出來：
- `{"installed": [<secret>]}`：區域變數 `block` 的那一行，**整個 secret 都在畫面上**；
- `{"installed": "x", "web": {…}}`：`text` 被截在 80 個字，這次沒露出來；但只要 secret 落在前 80 個字裡，就會露出來。

這兩種形狀都是人為造出來的，Google 給的檔案不會長這樣；UTF-16 的那一種比較可能真的發生。

**建議**：
- `read_client` 整段包在一個 `try` 裡，接住 `(OSError, ValueError, AttributeError, TypeError)`（`UnicodeDecodeError`、`JSONDecodeError` 都屬於 `ValueError`），一律回傳 `None`；
- **不要**把例外的文字帶出去（不寫 `{e}`，也不要讓它變成 `__context__` 往上傳）；
- 或者改成 `read_bytes()`，自己用 `decode("utf-8-sig", errors="strict")` 並接住錯誤，順便解決 T4 的 BOM；
- 加兩個測試：一個 UTF-16 的檔案、一個 `{"installed": [...]}`，斷言都回 `None`，而且首次設定退回內建的 client、沒有當掉。

## T2（Low～Medium）：README 的手動指令，把 secret 寫在命令列上

README 新加的範例：

```bash
rclone config create gdrive drive scope=drive.file \
    client_id=你的CLIENT_ID client_secret=你的CLIENT_SECRET \
    --config ~/.config/agora/rclone.conf
```

照著打，secret 會留在 shell 的歷史紀錄（`~/.zsh_history`）。issue #11 特別寫了 10-03 那次「secret 沒有出現在指令」，README 卻教相反的做法，和這張單「secret 只透過路徑讀」的精神也不一致。

**建議**：
- README 改成優先用首次設定的第二項；
- 如果要保留手動的方式，就讓值從檔案讀，不要打在命令列上。例如 `client_secret="$(python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["installed"]["client_secret"])' ~/Downloads/client_secret_….json)"`；
- 並且加一句：設定完之後，把下載的 JSON 移走或刪掉，因為值已經在 `rclone.conf`（權限 600）裡了。

## T3（Low，設計上的選擇）：argv 在授權期間，`ps` 看得到

`rclone config create … client_secret=…` 在等瀏覽器授權的整段時間（可能好幾分鐘），同一台機器上的其他使用者用 `ps` 都看得到 secret。D5 有寫這個代價，在單人使用的 Mac 上可以接受。

如果想連這個也避開：
1. 先由 agora 自己把 `[gdrive]`（`type`、`scope`、`client_id`、`client_secret`）寫進 `rclone.conf`，權限 600；
2. 再跑 `rclone config reconnect gdrive: --config …` 做 OAuth。

這樣 argv 裡就沒有 secret 了。要不要做，由 PM／使用者決定。
