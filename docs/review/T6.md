## Y1（Medium）：全部讀完之後再捲到頂，尾端會重複一次

`Preview.before` 同時代表兩件事：
- `0` 是「還沒讀」，`read_tail(before=0)` 讀的是**尾端**；
- 讀到檔案開頭之後，`before` **也是 0**。

`load_earlier` 沒有先檢查 `preview.more()`，就直接呼叫 `step()`，於是又讀一次尾端，接在最上面。

實測：
- 一個小的 `session.md`（標頭加兩則）：`step()` 第二次會再回傳內容，`text` 裡同一句出現 **2 次**；
- 在 app 裡，把預覽讀完，然後捲下來再捲到頂：「最後一則」從 1 次變成 **2 次**。

所有 30 KB 以內的 Session，第一次就讀完了，所以**只要捲到頂就會重複**。大的 Session 補到最上面之後，也是一樣。

**建議**：
- `load_earlier` 開頭加 `if not preview.more(): return`；
- 或者讓 `before` 一開始是 `None`（還沒讀），和「已經讀到開頭」的 0 分開；
- 加一個測試：小檔捲到頂兩次，內容不變。

## Y2（Medium）：補上一段之後，捲動位置沒有保持

`load_earlier` 用的是 `scroll_to(y=keep + lines)`。這裡的 `lines = len(preview.text.splitlines())` 是**整份文字的原始行數**，不是新補上那一段排版之後的高度。Markdown 排版之後的行數（換行、標題的空白）和原始行數差很多。

實測（Textual pilot，120×30，3 MB 的 Session）：
- 預覽高度 374 行，捲到頂之後補上前一段，變成 739 行（**多了 365 行**）；

測試 `test_scrolling_to_the_top_adds_the_step_above_and_keeps_the_line` 只驗了「有補上一段」；mutation「補上之後不調整捲動位置」**沒被抓到**。

## Y3（Low～Medium）：切在 code block 裡面時，後面的內容被排成程式碼

# 補記：Y6（High）：第二次補段直接跳到檔案開頭，中間的內容永遠不會出現

2026-10-03，review。這是寫驗收清單第 16 節時才發現的；上面「捲到頂補前一段 ✅」那一格**是錯的**。我當時只驗了第一次補段，以及第一步之後的提示行。那時「還有約 N KB」剛好是對的，所以沒有再往下追。

## 原因

`read_tail(path, before, size)` 的 `before`，意思是「從**尾端**往回算，已經讀過幾個 byte」：

```python
end = max(0, f.tell() - before)      # f.tell() 是檔案大小
```

但是它回傳的第二個值是 `start`，是「這一段從**檔案開頭**算的位置」，而 `Preview.step()` 把它原封不動存回 `self.before`：

```python
text, left = read_tail(self.path, self.before)
self.before = left
```

於是第二次的時候：
- `end = 檔案大小 - start` ≈ 30 KB；
- `start = 0`；
- 讀到的是**檔案最前面的 30 KB**；
- 然後 `before = 0`，`more()` 是 False，提示行消失。

第一步之後的 `hint()` 用的也是 `before`（= `start`）。這時「上面還有幾 KB」剛好就等於 `start`，所以看起來是對的，把問題藏住了。

## 實測（自編的檔案，T6 的程式直接讀）

| 檔案 | 第一步 | 第二步之後 |
|---|---|---|
| 約 100 KB（54 則） | 第 40～54 則，提示「還有約 72 KB」 | `more()` 是 False、提示行消失；54 則裡**少了 23 則**（第 17～39 則） |
| 約 2 MB（1063 則） | 第 1049～1063 則，提示「還有約 1972 KB」 | 一樣宣布讀完；1063 則裡**少了 1032 則**（第 17～1048 則） |

畫面上看起來，是「最後一段」的上面直接接著「開頭那一段」，中間沒有任何提示。只影響預覽，資料本身沒有問題。

現有的測試抓不到：`test_a_step_is_cut_on_a_boundary_and_breaks_no_character` 只看第二步也從 `## ` 開始、有兩個以上的 `## `；捲動的測試只看文字有沒有變長。

## 建議

- `Preview` 只記一種東西：**這一段的開頭在檔案裡的位置**（`start`）。
- `read_tail` 改成吃「讀到這裡為止」（`end`），回傳新的 `start`：
  - 第一次 `end = 檔案大小`；
  - 之後 `end = 上一次的 start`；
  - `start == 0` 就是讀完了。
- 這樣也順便解決 Y1：「還沒讀」可以用 `None`，不會和「讀到開頭」的 0 混在一起。
- `hint()` 用 `start` 算「上面還有幾 KB」（現在第一步就是這樣算的，剛好對）。
- **測試**：自編一個每則都有編號的檔案（例如驗收清單的 `grow.py`），一直 `step()` 到 `more()` 是 False，斷言：
  - 每一個編號都剛好出現一次（不缺，也不重複）；
  - 步數大約是 `檔案大小 / PREVIEW_CHUNK`。

這一項和 Y1、Y2 是同一塊程式，建議 impl2 一起修。驗收清單第 16 節的 16.10～16.12、16.14 已經標了依賴 Y1、Y2、Y6。
