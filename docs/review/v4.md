## 1. OKF frontmatter 是否符合 OKF v0.2 — ✅ 符合，有一個需要使用者確認的地方

| 規則（OKF v0.2） | 實作 | 結果 |
|---|---|---|
| `type` 是唯一必填 | `validate()`：沒有 `type` 就丟出 HeaderError；`user_updates`／editor 只允許 `Session` | ✅ |
| 其他欄位都是選填 | `_auto_header` 會填 `title`／`description`／`tags`／`generated`／`sources`／`id`／`refs`／`case`／`agora`；`status`、`verified`、`stale_after` 不填 | ✅ |
| 不認得的欄位要保留（消費端不得拒絕） | `overlay` 只會合併或覆蓋，不會丟掉任何欄位；editor 也是把整份標頭 round-trip | ✅ |
| `generated.by` 的 actor 慣例 | `opencode/<modelID>`（例如 `opencode/space-bunny-free`）、`claude-code/<message.model>` | ✅ |
| `sources[]` 的形狀 | `{id: "opencode:ses_…", title, author, last_modified}`；continue／merge 會另外加上父 Session | ✅ |
| 日期是 ISO 8601 UTC | 自動填的都是字串 `…Z`；**使用者給的日期不是**（V3） | ⚠️ |

**需要使用者確認（V6，Low）**：design 3.4 寫的是「`status` 不自動填（OKF 預設 `stable`）」。但使用者自己的 OKF 慣例（okf-format skill 的鐵則）是「**AI 寫的內容一律 `status: draft`，而且不得填 `verified`**」。agent 的對話紀錄算是 AI 產出，所以照這條規則應該要自動填 `status: draft`，否則用 MyBrain 的工具讀到這些 Session 時，會把它們當成 `stable`。這是使用者的決定，我不推翻，只提出來請使用者確認。另外，`verified` 用 `--header` 誰都可以加，CLI 沒辦法確認操作的人是不是本人，只能靠文件約束（V14，Low）。

## 2. 差分疊加 — ✅ 規則正確，但 value 的解析有問題（V2）

|---|---|---|
| 自動 → `--header-file` → `--header`（依序） | `user_updates` = `overlay(header_file, header_args)`，`_with_user` = `overlay(auto, updates)` | ✅ |
| mapping 遞迴合併，清單與純量整個覆蓋 | `overlay()`：兩邊都是 dict 才遞迴；其他一律覆蓋 | ✅（`generated.by=x` 會保留 `generated.at`） |
| 點路徑 | `parse_header_args` 會建出巢狀的 dict | ✅ |
| 同一個 key 以後面的為準 | 純量 ✅；但 `--header generated=x --header generated.by=y` 會報「衝突」，順序反過來則可以（V10，Low） | ⚠️ |
| 不含 `=` 就報錯 | ✅ | ✅ |
| `id`、`agora` 不能改；`type` 只能是 `Session` | `user_updates` 會擋；`_with_user` 會把系統欄位放回去；editor 也會擋 | ✅ |
| `refs`／`case` 要符合 ref 語法 | `user_updates` 的時候檢查，`_with_user` 會再跑一次 `validate` | ✅ |
| `tags`／`refs`／`sources`／`verified` 給單一值時，自動變成清單 | `LIST_KEYS` | ✅ |

**V2（Medium，已實測）**：value 一律經過 `yaml.safe_load`，只有「看起來像數字」的情況有特別保護。實測結果：

| 參數 | 存進去的值 |
|---|---|
| `description=把 CSV: 轉成表格` | `{'把 CSV': '轉成表格'}`（變成 mapping） |
| `description=步驟 #2 很重要` | `'步驟'`（`#` 之後被當成註解） |
| `title=no` | `False` |
| `title=null` | `None` |

使用者在 description 裡寫「：」或「#」很常見，而且這個錯誤**完全看不出來**。**建議**：只有在 value 是以 `[`、`{`、`"`、`'` 開頭，或者 key 屬於結構化欄位（`tags`、`refs`、`sources`、`verified`、`generated`、`stale_after`）時，才用 YAML 解析；其他情況一律當成字串。另外，`validate` 加上型別檢查：`title`／`description`／`status` 必須是字串，`tags` 必須是字串的清單。

**V3（Medium）**：`generated.at=2026-10-02T00:00:00Z` 會變成 `datetime`，`stale_after=2027-01-01` 會變成 `date`（已實測）。寫進 session.md 時是 YAML 的 timestamp；進索引時，`json.dumps(default=str)` 會把它變成 `2026-10-02 00:00:00+00:00`。結果是：(a) `--filter generated.at=2026-10-02T00:00:00Z` 比對不到；(b) `sort_date` 會混用兩種格式；(c) `show`／`edit` 讀的是索引裡的 JSON 版本，所以 edit 存回去的時候，日期就悄悄變成了字串。**建議**：`user_updates` 在回傳之前，把 date／datetime 一律轉成 ISO 字串（datetime 轉成 `%Y-%m-%dT%H:%M:%SZ`，date 轉成 `%Y-%m-%d`）。

## 3. `--filter` 的 `=`、`~=` 與 `text` — ✅ 正確

- 解析：用第一個 `=` 切開，前一個字元是 `~` 就是包含；value 裡可以有 `=`（`a~=b=c` → `('a',), '~=', 'b=c'`，已實測）。
- `=` 用 `str(item) == value`；`~=` 用 NFKC 加上 lower 之後的包含比對。清單欄位只要有一個成立就算（`tags=csv` ✅）。
- `text` 只能用 `~=`；第一個 text filter 會用 FTS5，少於 3 個字時用 `instr`；第二個以後在 body 裡比對，全部用 AND 串起來。
- `agent` 是 `agora.source.agent` 的簡寫 ✅。
- 小問題（V13，Low）：`text~=`（value 是空的）會比對到全部。建議改成報錯。

## 4. delete — ✅ 會進垃圾桶，也會擋住有子 Session 的（只限新格式，見 V1）

- 用的是 `rclone purge gdrive:sessions/<ULID>`。rclone 的 Drive backend，`--drive-use-trash` **預設是 true**（我用 `rclone help backend drive` 確認過說明），而 `~/.config/agora/rclone.conf` 裡**沒有** `use_trash` 的設定（我只用 `grep -c` 數了行數，結果是 0，沒有印出檔案內容）。所以會進 Drive 的垃圾桶。purge 在 Drive 上會照 `use_trash` 處理，這點是根據 rclone 的行為推論的，**沒有在 Drive 上實際驗證過**。建議在整合測試裡加一步：delete 之後，用 `rclone lsjson --drive-trashed-only` 確認它出現在垃圾桶裡（只在 agora-test 底下做）。
- 有子 Session 時：`index.children()` 會列出來，exit 1；這個檢查在 `--yes` 之前，所以加了 `--yes` 也照樣會被擋。delete 會先做一次**不節流**的 sync，其他機器剛建的子 Session 也看得到 ✅。
- 沒加 `--yes`：只印出要刪的對象，exit 1 ✅。
- 刪除時也會一起清掉本機的鏡像、索引、outbox ✅。
- 小問題（V11，Low）：如果一個 Session 只在 outbox 裡（還沒上傳成功），purge 會因為「找不到資料夾」丟出 StoreError，exit 2，本機的那一份也不會被刪掉。建議 Drive 上沒有的時候，就只刪本機的部分。

## 5. edit — ✅ 流程正確，有幾個 Low

- 有 `--header`／`--header-file` 時，照 3.5 疊加；都沒有時，用 `$VISUAL`／`$EDITOR`（再沒有就用 `vi`）打開**扣掉系統欄位**的 YAML，存檔之後檢查系統欄位和 `type`，然後跑 `validate`；驗證不過就丟出 HeaderError（exit 2），不存檔 ✅。
- raw 會保留：`fetch_raw` 會拿回原本的 bytes（並且檢查 md5），stage 時用的是同一個檔名，所以 Drive 上還是同一份 raw，push 也不會刪掉它 ✅。continue 的子 Session 記的 `raw_md5` 也不受影響 ✅。
- 標頭沒有變的時候，會印出 id 和「沒有變」，不會上傳 ✅。
- V7（Low）：edit 用的是**有節流**的 sync。如果 5 分鐘內另一台機器剛改過，這邊會用舊的標頭蓋過去。建議改成和 import／delete 一樣，不節流。
- V8（Low）：在編輯器裡改完、驗證失敗時，暫存檔會在 `finally` 裡被刪掉，使用者剛才改的內容就沒了。建議失敗時保留暫存檔，並且印出它的路徑。
- V9（Low）：每次 edit 都要先下載 raw，再重新上傳一次，大的 Session 會比較慢，而且離線時沒辦法 edit。可以考慮在 push 時，如果 Drive 上已經有同名、同 md5 的 raw，就跳過上傳。
- edit 讀的是**索引裡的 JSON 版本**的標頭，不是 session.md 本身，所以 V3 的日期問題會跟著存回去。V3 修好之後，這個問題就不存在了。

## 6. 舊格式的 session.md — ⚠️ V1（High）

agora-test 裡有之前整合測試、e2e、驗收留下的第 2／3 版 Session（標頭裡的 `relation`／`parents`／`source`／`raw` 都在頂層，沒有 `agora` 區塊）；如果使用者在正式的 agora/ 用過第 3 版，那裡也會有。我在 scratchpad 裡做了兩份舊格式的 session.md（父、子，子的 `parents` 指向父），`AGORA_RCLONE=/usr/bin/false`，實測結果：

| 動作 | 結果 |
|---|---|
| `validate` | 不會 crash，只警告「agora 標頭版本 None」 ✅ |
| 建索引、`search --filter text~=表格` | 搜得到；但日期欄和 agent 欄都是空的，顯示成 `None` |
| `index.children(<舊的父>)` | **`[]`**，舊的子 Session 沒有被認出來 |
| `agora delete session <舊的父>` | 沒加 `--yes` 時，會印出「會把…移到 Drive 垃圾桶」，exit 1。也就是說，**加了 `--yes` 就會被刪**，雖然它其實有子 Session（違反 5.6） |
| `agora edit session <舊的父> --header description=x` | **`非預期的錯誤：KeyError: 'agora'`**，exit 2 |
| `index.by_source("opencode", "ses_old")` | `[]`，所以重新匯入同一個來源時，會建一個新的 Session，而不是更新原本那個 |
| continue | `agora.raw` 找不到，所以**原生接續被悄悄降級成閱讀版注入** |

**建議**（大約 10 行）：`agora_of()` 在沒有 `agora` 區塊時，從頂層的舊欄位（`relation`、`parents`、`source`、`raw`、`created_at`、`updated_at`）組出一個相容的 dict；cmd_edit／import 的更新路徑寫回時，用 `setdefault("agora", {})`，並且把舊的頂層欄位搬進 `agora`，同時把 `type: session` 改成 `Session`、`note` 改成 `description`。這樣舊資料第一次被改寫時，就會自動升級。單元測試加上「舊格式的父與子：delete 會被擋、edit 成功並且升級、by_source 對得到」。
