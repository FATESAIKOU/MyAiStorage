## 2. `api.github.com` 早 9 秒的解釋（review M6 要求）

重測（2026-09-26 09:15 UTC，5 次、間隔 10s，容器與 googleapis 並列）：

```
sample1 container=[09:15:13] google=[09:15:14] github=[09:15:07]   # github 慢 6-7s
sample2 container=[09:15:24] google=[09:15:24] github=[09:15:17]   # 慢 7s
sample3 container=[09:15:35] google=[09:15:36] github=[09:15:29]   # 慢 6-7s
sample4 container=[09:15:46] google=[09:15:47] github=[09:15:40]   # 慢 6-7s
sample5 container=[09:15:58] google=[09:15:58] github=[09:15:50]   # 慢 8s
```

- **`api.github.com` 的 `Date` header 系統性慢 6〜8 秒**（重現兩次、方向一致），而 googleapis 與容器一致。
- 佐證：`api.github.com` 回應帶 `cache-control: public, max-age=60, s-maxage=60`（CDN 快取 60 秒）；`GET` 與 `HEAD` 的值相同、且 `Date` 對應的是**快取物件產生時間**，不是當下時間。
- 結論：那組樣本**不是容器時鐘問題，也不代表 GitHub 比容器慢**——是 CDN 快取讓 `Date` 過時。**外部時間對照一律用 googleapis（或 NTP），不用 `api.github.com`**；這也解釋了初版 `08:32:14` 的早 9 秒。
