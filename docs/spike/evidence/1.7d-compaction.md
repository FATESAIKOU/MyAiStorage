## 3. M3 補測：自動壓縮與工具輸出的 prune（2026-09-26 09:1x UTC）

主動 summarize 的樣本沒有工具輸出，且 `compaction.auto` 的路徑未測；本節補上。

### 3.1 自動壓縮（`compaction.auto=true`）

- 以 `OPENCODE_CONFIG_CONTENT` 把模型的 context limit 調低，讓長對話自然觸發自動壓縮；以 `opencode run` 連續對話。
- 結果：**自動壓縮會發生**且以 `part.type="compaction"`、`auto: true` 出現（實測 3 次；`agent=compaction` 的 stream log 佐證）。同樣是 append、不移除既有訊息；Session id 不變。
- **但 prune 在 `opencode run`（CLI）路徑下從未執行**（log 無 `pruning` 記錄、DB 無標記）。

### 3.2 prune 在本次於 API／serve 路徑觸發（CLI `opencode run` 樣本未觸發）

- 以 `opencode serve` + `POST /session/{id}/message`（TUI 走同一條）重測：log 出現 `message=pruning` → `message=found pruned=146130 total=146130` → `message=pruned count=1`。
- 對照組：以 `opencode run`（CLI）餵了同樣量級的工具輸出（每筆約 58 萬字元、累計遠超門檻），log 無 `pruning`、DB 無標記；目前證據只到「本次 prune 只在 serve（API／TUI）路徑被觸發」，不下「CLI 永遠不跑」的結論（`opencode run` 與 serve 走的是不同 entry，行為可能隨版本改變）。
- **prune 的機制**（binary 反組譯）：從最後往前掃 tool parts，跳過 `tool == "skill"`，累計估算 token 數；總量 `total > 40000` 且可回收量 `pruned > 20000` 時，對超過門檻的 parts 設 `state.time.compacted = <timestamp>`，並把輸出從模型上下文換成 `"[Old tool result content cleared]"`。
- 實測結果（含大量工具輸出的 Session）：turn 3 起標記生效，之後每輪新增 1 個標記；**只標記較舊的 tool parts**（新產生的不標）。

### 3.3 prune 對「匯出」的影響（關鍵）

- **被 prune 的 part 在匯出裡仍在、`state.output` 的內容完整**：before／after 匯出比對，被標記的 part `len_same=True`、內容雜湊 `hash_same=True`（例：584518 bytes／`47986946e9ff` 前後一致）。
- 標記只改變 `state.time.compacted`（新增）與模型上下文中的呈現（`"[Old tool result content cleared]"`）；**DB 與 export 的 `state.output` 沒有被清掉**。
- 因此：**Agora 的原始紀錄（export）在 prune 後仍保有完整工具輸出**，不需要靠 prune 前的快照；「prune 會讓既有內容消失」的假設**不成立**（當版）。
- 對 3.5 轉換器的影響：閱讀版要處理 `state.time.compacted` 標記（表示「模型上下文已清、原輸出仍在」），可據此決定呈現方式；這是新增欄位、不是內容遺失。

### 3.4 與自動壓縮的關係

- prune 與壓縮是兩個獨立機制：prune 只標記 tool parts，不建立摘要；自動壓縮會 append `compaction` part 與 summary。
- 兩者都會在 API／serve 路徑由 `SessionPrompt.run` 的同一段流程觸發（每次 run 結尾呼叫 `SessionCompaction.prune`）。
- 對 D4 的影響：**同步器（走 serve／API 或 CLI export 皆可）看到的 export 內容不因 prune 而消失**；若日後版本改為真的清除 `state.output`，才需要「prune 前快照」的對策——期 1 不需要，但建議在健康檢查或升級時留意此行為。

## 4. 對設計的影響

- 原風險「壓縮會讓匯出移除舊訊息、Agora 只能靠壓縮前快照保住內容」**不成立**（當版行為）：壓縮不移除訊息，既有訊息位置也不變；同步器不需要為壓縮做特別處理。
- 附帶注意（給 3.5 轉換器／2.4 閱讀版格式）：閱讀版要處理新型態的 part `compaction`（user 訊息）與 `info.summary=true`（assistant 訊息），否則摘要會被當成一般對話；摘要屬衍生物質，建議在閱讀版標記為「摘要」而非普通訊息。
- 自動壓縮（`compaction.auto`，預設 true）可能在長 Session 自動發生；行為同上（append），不影響接續點。
- **prune 的影響（M3 補測結論）**：prune 會標記既有 tool part（`state.time.compacted`），但**不清除** DB／export 裡的 `state.output`；Agora 的原始紀錄因此仍保有完整工具輸出。閱讀版與轉換器（3.5）要處理 `state.time.compacted` 標記；D4 不需要為 prune 做「同步間隔壓縮」的特別安排（但建議在健康檢查留意未來版本是否改為真清除）。
