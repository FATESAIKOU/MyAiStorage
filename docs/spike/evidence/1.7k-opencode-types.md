## 2. 附件與段落型別原文（FilePart）

在 opencode 1.18.32 中，所有檔案與圖片附件均以 `type: "file"` 表示（opencode 原始紀錄無獨立之 `"image"` part 型態，圖片以 `mime: "image/*"` 區分）：

```typescript
export interface FilePart {
  type: "file";
  mime: string;        // 必填：MIME 類型，例如 "application/json", "image/png"
  filename?: string;   // 選填：檔案名稱，缺少時為 undefined / null
  url: string;         // 必填：資料 URL ("data:<mime>[;base64],...") 或外部/本機 URL
  source?: string;     // 選填：附件來源
}
```

### 欄位約束與轉換器處理規則：
1. **`mime` (必填)**：缺少時判定為結構損毀，拋出 `ConversionError`，絕不自行補上預設值（如 `"image/png"` 或 `"application/octet-stream"`）。
2. **`filename` (選填)**：缺少時，在文字標示中呈現「（無檔名）」，絕不捏造虛構檔名（如 `"image.png"` 或 `"unnamed_file"`）。
3. **`url` (必填)**：
   - 若為 `data:` URL，支援標準 RFC 2397 格式（`;base64` 採嚴格驗證解碼；非 base64 採百分比編碼 `unquote_to_bytes`）。
   - 若為外部/本機 URL（非 `data:`），因原始內容未內嵌於匯出 JSON 中，轉為文字段落 `[附件：<filename> <mime>，內容不在匯出中]`，絕不捏造虛假雜湊。

## 3. 中止錯誤型別（MessageAbortedError）

在 opencode 中，使用者主動中止助理生成時，訊息中繼資料記錄於 `info.error`：

```typescript
export class MessageAbortedError extends Error {
  name: "MessageAbortedError";
}
```

- 匯出形狀：`message.info.error = { "name": "MessageAbortedError", "message": "Message was aborted by user" }`
- 判定規則：`info.error` 為物件且其 `name == "MessageAbortedError"` 即判定為已中止（`in_progress = False`）。
