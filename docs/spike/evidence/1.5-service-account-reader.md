- 執行時間：2026-09-26 11:20〜11:27 UTC（20:20〜20:27 JST）
- 執行者：impl1
- 前置：1.1（`sa-reader.json`、`SA_EMAIL=spike-reader@aistorage-spike-1-260926.iam.gserviceaccount.com`）、**專屬前綴 `agora-read/`**（H1）；SA 在 `aistorage-spike` 為檢視者
- **SA conf（本項建立）**：`~/.config/aistorage-spike/rclone-sa-reader.conf`（600）——`type = drive`、`scope = drive`（**H5：完整 scope，不是 `drive.readonly`**）、`service_account_file = ~/.config/aistorage-spike/sa-reader.json`、`root_folder_id = SPIKE_FOLDER_ID`（H6）。理由：要證明的是 **Drive ACL 只有 reader**，不是 token 的 scope；住民拿到 SA 金鑰後可自己換完整 scope 的 token，唯讀 scope 下「寫不進去」什麼都證明不了。

## 2. Clone（pass，SA 是唯一憑證）

容器內 `RCLONE_CONFIG` 只指 SA conf（`/secrets` 沒有 committer conf）：

```
$ git clone -b main "annex::1e945d78-4cdf-4715-9374-5968bd11c1e7?encryption=none&type=rclone&rcloneremotename=gdrive&rcloneprefix=agora-read" sa-clone
clone rc=0 ms=13416
$ git log --oneline
c1ceaa2 add large annex file + small file
ad8c9ed init: agora-read
```

- clone 後的 remote：`origin annex::1e945d78-…&rcloneprefix=agora-read`（證明來源是 Drive repo，不是本機快取或 committer）。
- `git annex init sa-clone` 後 `git annex get read-large.bin` → `(checksum...) ok`；`sha256sum read-large.bin`＝`2041401cecf73d6511e6cdbec208624b71361902613b4920251d01aa9a180d37`＝annex key 內的 SHA256（`SHA256E-s524288--2041401c…`）。

## 3. 依 annex key 直接取物件（pass）

```
$ git annex whereis read-large.bin
whereis read-large.bin (3 copies)
  	1c89a2c9-… -- sa-clone [here]
  	1e945d78-… -- drive [origin]
  	8958f653-… -- spike-read
$ git annex lookupkey read-large.bin
SHA256E-s524288--2041401cecf73d6511e6cdbec208624b71361902613b4920251d01aa9a180d37.bin
```

- **key 對應 Drive 路徑的規則**（供 D5 結論）：`agora-read/<key 檔名>`——special remote 的 `rcloneprefix=agora-read` + 物件檔名＝完整 key（`SHA256E-s<size>--<sha256>.bin`），**encryption=none、未 chunk** 時 key 直接對到物件，不需查 annex 索引。
- SA 以 `rclone cat gdrive:agora-read/SHA256E-s524288--…` 取回 → `sha256sum`＝`2041401c…` 與 key 完全一致。

## 4. 寫入失敗（pass）

所有操作用 `spike/probe/drive_probe.py --cred sa-reader.json`（依 file id；token 只在記憶體，輸出只有狀態與 reason）：

| 操作 | 目標 | 結果 |
|---|---|---|
| `files.create` 檔案 | `SPIKE_FOLDER_ID` | **403** `insufficientParentPermissions` |
| `files.create` 資料夾 | `SPIKE_FOLDER_ID` | **403** `insufficientParentPermissions` |
| `files.create` 檔案 | repo 資料夾 `agora-read`（`1InFRcB8E_1g7ys3AypzdXVqjIsnYGQ5b`） | **403** `insufficientParentPermissions` |
| `files.create` **與 GITMANIFEST 同名** | repo 資料夾 | **403** `insufficientParentPermissions` |
| `files.create` 檔案 | 讀取視圖 `readview`（`1aT4CTgDE8gUN62Y5s9G-UT9OZ6laMhP0`） | **403** `insufficientParentPermissions` |
| `files.update`（改名） | committer 建的既有檔 | **403** `insufficientFilePermissions` |
| `files.update`（改內容） | 同上 | **403** `insufficientFilePermissions` |
| `files.delete` | 同上 | **403** `insufficientFilePermissions` |
| `files.delete` | repo 內既有 GITBUNDLE（`1rAhB2tv…`） | **403** `insufficientFilePermissions` |
| `permissions.create` | 既有檔 | **400** `invalidSharingRequest`（"you do not have permission to share"） |

- 全部是**權限理由的 403／400**（不是 404——SA 看得到這些資料夾，是 ACL 只給 reader；也不是唯讀 scope 造成）。
- **`git push` 與 `git annex copy --to origin` 也被拒**：`Failed to copy: googleapi: Error 403: Insufficient permissions for the specified parent., insufficientParentPermissions`；`copy: 1 failed`。
- 事後由 committer 確認：`SPIKE_FOLDER_ID` 根目錄無新檔（唯一 `1.5-sa*` 是測試用的目標檔、owner 是專用帳號本人，已永久刪除）；既有檔 `name`／`md5` 不變；`agora-read` 物件數仍為 5（2 個 GITBUNDLE 都還在）；remote main 仍是 `c1ceaa2`（SA 的 push 沒有生效）。

**正向對照（N6）**：SA 用自己的金鑰跑 `battery`——`create_folder.http=200`（在 SA 自己的空間），但 `create_file.http=403 reason=storageQuotaExceeded`（"Service Accounts do not have storage quota"）。→ SA **根本沒有儲存配額**，所以它連「自己空間」都建不了檔案；對別人的資料夾更只有 reader 權限。SA 建的 battery 資料夾（`1tUZwDr4Ma_qDVFMvyEk9hWuYOGJbd2xf`）已由 SA 自己刪除（204）。

**整體：pass。** 供 1.9 的注意事項：
- **SA conf 需要路徑覆寫**才能在容器內用（本項以 `RCLONE_CONFIG_GDRIVE_SERVICE_ACCOUNT_FILE` 環境變數；正式部署要把 `service_account_file` 指向容器內路徑，或由 MLP 發放時處理）。
- **SA 沒有任何儲存配額**（`storageQuotaExceeded`）：這是 Drive 對 service account 的平台限制，代表 SA 只能當讀取身分，不能當任何寫入端——與 D3 的設計一致，但值得寫進 design（SA 不能建收件匣、不能當寫入者）。
- key → Drive 路徑規則：`<rcloneprefix>/<完整 key 檔名>`，`encryption=none`、未 chunk。**這確認 D5「依 annex key 直接取收容產出」可行**（1.4i／1.7 的 manifest 用固定 id，這一項用 key 路徑，兩者互補）。
