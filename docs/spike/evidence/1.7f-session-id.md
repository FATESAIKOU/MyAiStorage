# 1.7f skill 能不能取得目前的 Session id

- 執行時間：2026-09-26 08:1x〜08:3x UTC
- 執行者：impl3；容器 `oc17-main`（arm64）
- 判定：**pass**（有確定性、可寫成指令的取得方式；見第 1、2 節兩種）

## 1. 首選：plugin tool（`tool.execute` 的 context 帶 sessionID）

opencode 的 plugin 註冊自訂 tool 時，`execute(args, context)` 的 `context.sessionID` 就是**目前 Session** 的 id（SDK 型別：`ToolContext.sessionID`；plugin hook 的 `input.sessionID` 同）。實測：

```js
// /work/.opencode-plugin-sessionid.js，載入於 opencode.json 的 plugin 陣列
export const SessionIdInfoPlugin = async ({ directory }) => ({
  tool: {
    where_am_i: {
      description: "Return the current opencode session id as JSON. …",
      args: {},
      execute: async (_args, context) =>
        JSON.stringify({ sessionID: context.sessionID, directory: context.directory }),
    },
  },
})
```

執行：

```bash
$ opencode run --title "SPIKE-1.7-F" -m … --auto "Call the tool where_am_i … reply with exactly the sessionID …"
$ opencode session list --format json | jq -r '.[] | select(.title=="SPIKE-1.7-F") | .id'
ses_f234a5dfaffeczJtKJJ3fyVgdZ
```

- 匯出中的 tool part：`output = {"sessionID":"ses_f234a5dfaffeczJtKJJ3fyVgdZ","directory":"/work"}`。
- **與 `session list`（1.7a 的列舉結果）比對相等**：模型最終輸出即該 id，與 list 的 id 一致 → 不是靠「最近一個」猜測。
- 這是 skill 可直接使用的方式：把 plugin 隨住民容器一起安裝（Atelier／5.4 的 skill 呼叫這個 tool），或直接在 skill 流程中用同一 plugin 的 hook。

## 2. 替代：`shell.env` hook 把 id 注入 shell 環境變數

```js
export const SessionEnvPlugin = async () => ({
  "shell.env": async (input, output) => {
    if (input.sessionID) output.env.SPIKE_SESSION_ID = input.sessionID
    if (input.callID) output.env.SPIKE_CALL_ID = input.callID
  },
})
```

實測：Session 內 `bash` 工具執行 `echo SID=$SPIKE_SESSION_ID` 得到 `SID=ses_f23285e27ffeGp73GhqmtbHoIn`，與該 Session 的 list id 一致。

- 註：opencode 對 bash tool **預設不注入** Session id（1.7a 的能力盤點與 `env` 測試：session 內 `env` 只有 `AGENT=1 OPENCODE=1 OPENCODE_PID=…`，沒有 session id）；要靠 plugin 注入。
- `OPENCODE=1`／`OPENCODE_PID` 存在但不是 id；`AGENT=1` 是標記。

## 3. 不可靠的方式（排除）

- `opencode session list` 取「最近一個」→ 猜測，排除。
- `OPENCODE_PID`→ 程序，非 Session，排除。
- 環境變數（無 plugin）→ 沒有 id，排除。

## 4. 判定

Pass：有兩種確定性取得方式（plugin tool 的 `context.sessionID`；`shell.env` 注入），都不需猜測、可寫成指令／plugin；與列舉結果實測相等。D10 的認領不需要改設計。
