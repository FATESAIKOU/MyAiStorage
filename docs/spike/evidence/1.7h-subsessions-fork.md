# 1.7h 子 Session（task 工具）與 fork 匯出時的樣子

- 執行時間：2026-09-26 08:0x〜08:3x UTC
- 執行者：impl3；容器 `oc17-main`（arm64）
- 判定：**go-with-caveat**（子 Session 與母 Session 完全分離，可用 API／DB 遞迴列舉並歸屬；fork 的關係只在標題字串、訊息 id 全部重新產生——給 D4／5.2／3.5 轉換器的明確規則見第 2、4 節）

## 1. 子 Session（task 工具）

觸發：

```bash
$ opencode run --title "SPIKE-1.7-TASK" -m … "You MUST use the task tool now. Call task with description 'sub-test' and prompt 'Reply with exactly SUB-OK and nothing else.'"
```

- 母 Session：`ses_f234ccff5ffeNh136EyW4hG9Kv`（3 則訊息：user → assistant（含 `tool:task` part）→ assistant（總結））。
- 子 Session：`ses_f234cb6b9ffeN5v0xeYGxxhS0w`，**有自己的 id**、**不在 CLI `session list`** 裡（list 只列主 Session）。
- DB `session.parent_id`：子 Session = 母 Session id；母 Session = NULL。`session list` 不顯示 `parentID` 欄。

### H1 補測：子 Session 的列舉路徑（2026-09-26 09:0x UTC）

| 路徑 | 結果 |
|---|---|
| API `GET /session/{id}/children` | **可列舉**：回傳 `{"id":"ses_f234cb6b9ffeN5v0xeYGxxhS0w","parentID":"ses_f234ccff5ffeNh136EyW4hG9Kv","title":"sub-test (@general subagent)"}` |
| DB `select id, parent_id from session where parent_id is not null` | **可列舉**（同一筆） |
| 遞迴（子再往下查 children） | 回傳 `[]`（本樣本無孫）——同一手法可遞迴 |
| CLI `opencode session list --format json` | **不含**子 Session |
| API `GET /session`（全域清單） | **含**子 Session（實測回傳該 id；與 CLI 不同！） |
| `opencode export <childID>` | 直接指定 id 可匯出（rc=0，3834 bytes） |

- 結論：**遞迴列舉可行**（`GET /session/{id}/children` 或 DB `parent_id`），子 Session 可同步、可匯出；D4／5.2 的同步器必須遞迴列舉子 Session（H1）；5.4 的認領需限定主 Session（plugin 見 `parentID` 拒絕）。
- 注意：CLI `session list` 與 API `GET /session` 的範圍不同（前者不含子 Session、後者含）——同步器不要只依賴 CLI list。

### 母 Session 匯出中的表示

- `messages[1].parts` 內有一個 `type: "tool"`、`tool: "task"` 的 part，`state`：
  - `state.metadata`：`{"parentSessionId":"ses_f234ccff5ffeNh136EyW4hG9Kv","sessionId":"ses_f234cb6b9ffeN5v0xeYGxxhS0w","model":{…},"truncated":false}`
  - `state.output`（給模型看的摘要）：`<task id="ses_f234cb6b9ffeN5v0xeYGxxhS0w" state="completed">…<task_result>SUB-OK</task_result></task>`
  - `state.status="completed"`。
- **子 Session 的完整訊息不在母 Session 的匯出裡**（母的 `messages` 只有 3 則；`grep SUB-OK` 只命中 task output 的 `<task_result>` 一行）。

### 子 Session 自己的匯出

```bash
$ opencode export ses_f234cb6b9ffeN5v0xeYGxxhS0w > Etask-child.json   # rc=0
```

- 內容為子 Session 自己的對話（2 則：user prompt、assistant `SUB-OK`）；`info.parentID` = 母 id。
- part 只有 `step-start`／`text`／`step-finish`；**不含**母 Session 內容。

### 給 3.5 轉換器的規則

- 每一則訊息都能歸給正確的 Session：母 Session 的 task part 記有子 id；子 Session 自己有 `parentID`。**不會混在一起。**
- 閱讀版若要呈現「子任務的完整內容」，需另外匯出子 Session（以 `parent_id` 或 task part 的 id 連結）。

## 2. fork（三種觸發：API 兩種、CLI 一種）

| 觸發 | 結果 |
|---|---|
| `POST /session/{id}/fork {}`（API，全量） | 新 id `ses_f234d300cfferHf0riq6LaQ2IJ`，10 則（= 母全量） |
| `POST /session/{id}/fork {"messageID":…}` | 新 id `ses_f234d22ffffe1p7g76MsdtVK00`，2 則（到指定訊息為止） |
| `opencode run -s $SID --fork "…"`（CLI） | 新 id `ses_f23252f2fffehWgbbBPo6rWOn9`，6 則（母的當下內容＋新的 1 輪） |

### 匯出結構（關鍵事實）

- fork 的新 Session：`info.parentID` **不存在**（NULL）；DB `parent_id` 也 **NULL**。
- 與母 Session 的關係**只表現在標題字串**：`"SPIKE-1.7-S1 (fork #1)"`（三次 fork 標題完全相同，**沒有唯一的 fork 序號**）。
- **訊息 id 全部重新產生**：fork 複製的每一則訊息都有新 `msg_…` id（內容與 `time` 保留，`sessionID` 指向新 Session）。所以「訊息 id 不跨 fork 穩定」。
- 順序（index）與內容保留：fork-at-2 的前 2 則與母的前 2 則內容一致（雜湊相同），只是 id 換新。
- 母 Session 不受 fork 影響（fork 後母的 id 集合不變；fork 是複製）。

### 給 3.5 轉換器與 1.7c 的注意

- fork 出的 Session 在 Agora 看是一個**全新的 Session**（有自己的 id、沒有 parent 欄位），與母 Session 的關聯只能靠標題（不可靠）或外部紀錄（例如 skill 在 fork 後主動寫參考 Link，見 D10 的「參考」）。**不建議**用標題解析。
- 因為訊息 id 會重生成，**接續點不能跨 fork 沿用**；fork 後的接續點要用 fork 自己匯出的訊息 id（1.7c 結論不變）。
- 期 1 的 E2E 沒有用到 fork；此項為 go-with-caveat（子 Session 結構明確、轉換器可歸屬；fork 的關聯表示薄弱，回饋 D4／3.5）。
