# 1.7i 匯出內容不含帳號與憑證

- 執行時間：2026-09-26 08:2x〜08:3x UTC
- 執行者：impl3；容器 `oc17-main`（arm64）
- 判定：**pass**

## 1. 實際 key 與憑證形狀比對（只記次數）

對象：`Ef.json`（一個用過 LLM 的測試 Session 的匯出；LLM key 以唯讀掛載在 `/secrets/ollama-cloud-key.txt`，opencode 以 `~/.local/share/opencode/auth.json` 使用它）。

```bash
$ grep -cFf /secrets/ollama-cloud-key.txt Ef.json
0
$ grep -cE '<第三節的憑證形狀正規式>' Ef.json   # client secret 前綴、access／refresh token 前綴、PAT 前綴、私鑰標頭
0
```

- 實際 key 命中 **0 次**；憑證形狀命中 **0 次**。（為避免掃描永遠誤報，這裡不貼形狀本身，只寫比對了哪幾類：client secret 前綴、access token 前綴、refresh token 前綴、GitHub PAT 前綴、私鑰標頭。）
- 匯出不含 `auth.json` 的內容或引用（`grep -c 'auth.json'` → 0）。

## 2. 頂層結構與欄位名稱（不貼值）

- 頂層鍵：`info`、`messages`。
- `info` 欄位名：`agent, cost, directory, id, model, path, permission, projectID, slug, summary, time, title, tokens, version`。
- 訊息 `info` 欄位名：`agent, id, model, parentID, path, providerID, role, sessionID, summary, time, tokens`（`parentID` 只在子 Session 出現）。
- part 欄位名：`callID, cost, id, messageID, reason, sessionID, state, text, time, tokens, tool, type`。
- 與 provider／憑證相關的欄位只有**設定類的識別**：`model.providerID`、`model.id`（例如 `ollama-cloud` / `deepseek-v4.1-flash`）、`info.permission`（permission 規則陣列，內容為 `question`／`plan_enter`／`plan_exit` 的 allow/deny，非憑證）。**沒有** apiKey 欄位、authorization 欄位、任何憑證義的 token 欄位、帳號 email 欄位（以欄位名清單逐一核對）。
- 搜尋 `ollama` 字樣 4 次：全部是 `providerID`／model 識別，不是 key（key 比對 0 命中已證）。

## 3. 判定

Pass：實際 key 0 命中、憑證形狀 0 命中、無帳號或憑證欄位區塊。未違反 spec「Agora MUST NOT 保存來源應用的憑證」。無需新增過濾規則（1.7i 的 fail 類別不成立）。
