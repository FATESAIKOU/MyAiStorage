## 釘選值形狀（H1）

```json
{
  "state": "promoted",
  "refs": {"refs/heads/main": "ca077e5b…", "refs/heads/git-annex": "a51d0562…"},
  "manifest_sha256": "81aad756…",           // GITMANIFEST 內容 sha256
  "manifest_name": "GITMANIFEST--c2febd2f-…",
  "manifest_bundles": ["GITBUNDLE-…", …],   // manifest 引用的 bundle 清單
  "annex_objects": {"SHA256E-s204800--cda04a97….bin": "cda04a97…"}
}
```

可信集合**由內容推導**：manifest 內容 sha256 決定誰是真 manifest；bundle 必須「被真 manifest 引用」且「檔名內嵌的 size/sha256 與內容相符」；annex 物件必須「檔名 sha256/size 與內容相符」。列舉只提供候選，不提供信任。`.bak` 允許等於目前或上一個 manifest 的內容雜湊（本機 `pin.json` 帶 `prev_manifest_sha256`）。

## 測試結果

### 0. 基準（PASS）
`prepare` 於乾淨狀態：parents OK、clean 0 移動、verify refs 與 manifest 內容 sha 等於 promoted、`prepare: OK`（`10b-baseline-prepare.txt`）。

### 1. H1(a) push 後、轉正前中斷 → 下一輪自動恢復（PASS）
- 新 commit 推上（`main=494ac08f…`），**不執行 after-push**（模擬 runner 被 cancel）；`pin.pending.json` 留在磁碟、`pin.json` 還是舊的。
- 下一輪 `prepare`：`settle` 偵測 pending → 快照＋內容重放 → **唯一重放且 refs 等於 pending → 自動轉正**（`494ac08f…`）→ clean **0 移動**（沒有把真檔當 unknown）→ verify OK、pending 刪除（`30-h1a-autorecover.txt`）。
- 對照的錯誤路徑（kill 於「record-pending 之後、push 之前」）：pending 的 refs 在遠端不存在 → 重放失敗 → settle 比對遠端等於 promoted → **丟棄未生效的 pending** → 正常繼續（`46-kill-before-push.txt`）。

### 2. H1(b) push 與記錄之間注入 → 不得漂白（PASS）
- push 完成後、尚未記錄 pending 的窗口，C 注入一致偽造對（假 manifest＋自製 bundle）。
- 下一輪 `prepare`：snapshot 看到 3 個 manifest（1 假＋1 真＋1 `.bak`）→ 重放顯示**假 manifest 重放出的 refs 是舊的**（main 停在上上版、git-annex 是偽造值）→ 不相等 → 不被信任。
- settle 轉正後 clean：假的 manifest 與假 bundle **被移到隔離**（`manifest-內容不符`、`bundle-未被引用或雜湊不符`），真檔（7 筆含 annex 物件）全數保留（`33-h1b-prepare.txt`）。

### 3. H2 全 ref 核對（PASS）

- 先證明攻擊有效：**naive clone**（不核對）拿到的 `git-annex` 是偽造的（`c3df98ae…`、`rcloneprefix=agora-1.4f3-attacker/`），main 是真的（`23-h2-naive-clone.txt`）。

- `prepare` 的完整流程亦在清掃階段把假 manifest／假 bundle 隔離（`24-h2-v2-check.txt`）。
- **多餘 ref**（H2 的「不能多也不能少」）：C 上傳一個含 `refs/heads/extra` 的 bundle＋fake manifest → `check` 因 ref 集合多一個而 fail-closed（`35-h2-extra-check.txt`）。

### 4. M1 驗證腳本（PASS）
- `f3_verify_remote.sh` 一律 `git clone -b main --single-branch`，比對 `refs/remotes/origin/main` 與 `git ls-remote` 的全部 ref（不依賴 remote HEAD）；log 用 `mktemp`＋trap 刪除；ls-remote 在專用 scratch repo 內執行（實測 `annex::` 的 helper 需要 repo context；`f3-verify-dbg.txt`）。
