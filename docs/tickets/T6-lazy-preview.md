# T6：預覽只讀、只排需要的那一段（兩個分頁）

2026-10-03，使用者回報、PM 查明。狀態：待做（T3 歸檔之後）。

## 現象

互動模式的 Agora 分頁，上下移動游標很慢；pull 過也一樣。未匯入分頁比較快。

## 原因（PM 量測）

- Agora 分頁每次游標移動，都在主執行緒把整份 `session.md` 的內文讀出來，再排成 Markdown（`agora_preview` → `put_preview` → `Markdown(history)`），排完才回應下一次按鍵。
- 未匯入分頁先只顯示最後一則，全文在背景載入；但載入的也是整份閱讀版，載完一樣要整份排版。
- 使用者本機的 `session.md` 是 340 KB～3 MB。用自編的 2.9 MB 文字量（rich，寬 100）：
  - 讀整檔 2 ms；
  - 整份排版 0.72 秒；
  - 只排最後 30 KB 是 31 ms。

## 使用者的決定

原話：「先排最後一段，往上捲再補」，「未載入的部分可能可以用相同技術 總之只需要讀出需要的東西 然後高速化排版」。

## 要做的（兩個分頁共用同一套）

| # | 內容 |
|---|---|
| 1 | **只讀需要的**：從檔案尾端往回讀一段（約 30 KB，用 seek，不讀整個檔）。Agora 分頁讀鏡像的 `session.md`（略過標頭），未匯入分頁讀全文快取 `reading/<agent>/<id>.md`；快取還沒有時照舊在背景建，建好再讀尾端。往上捲時才讀前一段。切段要切在 `## ` 標題或空行上，不切斷一則訊息；多位元組字元不切壞 |
| 2 | **只排那一段**：預覽區只排已讀出的段落；往上捲到頂時，接著讀、排前一段並補在上面，捲動位置保持在原本看的那一行 |
| 3 | 還有更早的內容時，最上面一行「↑ 往上捲載入更早的內容（還有約 N KB）」；全部補完就不顯示 |
| 4 | 游標停下來約 150 ms 才更新預覽；快速上下移動時不讀也不排 |
| 5 | 測試：自編的數 MB 內文——移動游標不讀整檔、不排整份；捲到頂會補前一段；切段不切斷訊息與多位元組字元；兩個分頁都有 |
| 6 | 行數：只記錄，不擋（使用者 10-03：品質之後統一開 issue） |
