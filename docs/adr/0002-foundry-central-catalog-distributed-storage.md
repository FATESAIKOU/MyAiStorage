# Foundry：管理集中、儲存分散

Foundry 用一份產出目錄登錄所有產出，但只有沒有自己家的「收容產出」（簡報、圖片、影片、一次性報告）的真本放在 Foundry。程式碼、專案文件、跟著 PR 走的報告這類「原處產出」，真本留在它自己的 repo，Foundry 只記出處。使用者原本傾向全部集中，但儲存面集中有三個硬傷：專案 repo 的 CI、PR 流程會斷，否則就得維護兩份真本；GitHub 上 public 與 private 無法放在同一個 repo；影片超過 GitHub 的大小限制。「好管」的收益大部分來自管理面，而管理面集中不需要搬動任何檔案。

## Consequences

- 目錄會過期（漏登錄、死連結）是這個做法的主要風險。緩解方式是已知產出位置定期自動收錄、定期檢查死連結（期 2）；期 1 由員工明確登錄。
- 「集中保存」這一項收益拿不到：專案 repo 被刪，Foundry 就只剩一條死連結。之後以「重要產出快照」補上（期 3）。
