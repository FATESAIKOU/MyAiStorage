# interactive-mode Specification

## Purpose
互動模式（只打 `agora`）一次處理多個 Session：勾選、全選、看進度、中斷，並看得出哪些 Session 雲端已經沒有；所有動作都經過指令模式，行為與指令模式相同。
## Requirements
### Requirement: 動作作用在勾選的列
merge MUST 作用在 Agora 頁勾選的列（至少兩個）。delete、pull、push MUST 作用在 Agora 頁勾選的列，沒有勾選時作用在游標那一列。未匯入頁的 import（Enter）與 pull（`p`）MUST 作用在勾選的列，沒有勾選時作用在游標那一列。continue（Enter）與 edit（`e`）MUST 只作用在游標那一列。「勾選的列」MUST 只算目前看得到（篩選之後）的列；被篩選掉但仍勾選著的列 MUST NOT 被送進動作，標題列 MUST 顯示「另有 N 個勾選被篩選掉」（review V4）。merge 的來源順序 MUST 是畫面上由上到下的順序。動作成功後勾選 MUST 清掉；失敗或中斷時 MUST 保留，方便重跑。

#### Scenario: 刪除勾選的
- **WHEN** 在 Agora 頁勾選三列後按 `d` 並確認
- **THEN** 這三個 Session 被送進一個 delete 指令

#### Scenario: 篩選掉的勾選不算
- **WHEN** 勾選三列後用篩選把其中一列藏起來，按 `d`
- **THEN** 只有看得到的兩列被刪，標題列提示有一個勾選被篩選掉

#### Scenario: 沒勾選時匯入游標那一列
- **WHEN** 未匯入頁沒有勾選任何列，按 Enter
- **THEN** 只有游標那一列被匯入

### Requirement: 全選切換
`a` MUST 切換目前看得到（篩選之後）的列：沒有全部勾選時全部勾選，已經全部勾選時全部取消。篩選掉的列的勾選狀態 MUST NOT 被改變。空白鍵勾選時游標 MUST NOT 移動。

#### Scenario: 切換兩次
- **WHEN** 清單有兩列、都沒勾，按 `a` 兩次
- **THEN** 第一次後兩列都勾選，第二次後都取消

### Requirement: 進度與中斷
import、merge、delete、pull、push MUST 在等待視窗裡執行，視窗 MUST 有進度條（依指令輸出的 `k/N` 更新）與最新的一行輸出。按 Esc MUST 中斷這個動作（包含它啟動的 agent，例如寫要約的 opencode）：先送 SIGINT，5 秒內沒停就送 SIGTERM，再 5 秒就 SIGKILL，都對整個 process group（review V2）。子程序 MUST NOT 讀得到使用者的鍵盤輸入（review V1）。進度 MUST 只從以 `[agora]` 開頭、含 `k/N` 的行讀（review V8）。結果視窗 MUST 依 exit code 說明：成功、部分失敗、已存進 outbox 等下次上傳、已中斷（review V6）。中斷後，結果視窗 MUST 說明「重跑同一個動作會接著做」，關掉之後回到清單（review Q4）。

#### Scenario: 看得到進度
- **WHEN** 匯入五個 session
- **THEN** 進度條顯示**已經做完**的個數：從 0/5 起，收到第 5 個 `5/5` 時是 4/5；指令正常結束（exit 0）時進度條才到 5/5，結果視窗說「完成」

#### Scenario: 中斷 merge
- **WHEN** merge 寫第二個來源的要約時按 Esc
- **THEN** 動作停止、回到清單；再對同樣的列執行 merge 時，第一個來源的要約被沿用

### Requirement: 雲端欄與 pull／push 的選項
Agora 頁 MUST 有「雲端」欄，雲端有的顯示 ✓、雲端沒有的顯示 ✗、還沒上傳的顯示「未上傳」。pull 的確認視窗 MUST 有預設不勾的「雲端沒有的就刪掉本機的」，勾了等同 `--not-exist-delete`；push 的確認視窗 MUST 有預設不勾的「雲端沒有的就傳回去」，勾了等同 `--not-exist-upload`。

#### Scenario: 看出被別台刪掉的
- **WHEN** 某個 Session 被另一台機器刪掉，這台同步之後
- **THEN** 它的「雲端」欄顯示 ✗

#### Scenario: 對雲端沒有的接續
- **WHEN** 對雲端欄是 ✗ 的列按 Enter 接續
- **THEN** 不開 agent，畫面顯示指令模式的拒絕訊息與兩個選擇

### Requirement: 按鍵
按鍵分成兩套，依焦點在清單（左）還是預覽區（右）而不同。

- 清單那一邊：清單本身，以及清單的篩選框。
- 預覽區那一邊：預覽區本身，以及預覽區的搜尋框。

兩邊共用的 MUST 只有兩個：
- `Tab`、`shift+tab`：在清單與預覽區之間切換焦點。
  - 從清單的篩選框切出去時，和在篩選框按 Enter 一樣：篩選框收起來，篩選照樣生效。
  - 從預覽區的搜尋框切出去時，搜尋框關掉，還沒送出的字丟掉，標亮保留。
- `q`：離開。
  - 篩選框、搜尋框有焦點時，`q` 是打字，不是離開。

焦點在清單時，按鍵 MUST 是：
- ↑↓ 移動；
- `[`、`]` 換頁（Agora／未匯入）；
- 空白勾選，`a` 全選切換；
- `/` 篩選，ctrl+t 切換標題與內文；
- Enter（Agora 頁接續、未匯入頁匯入），只在清單本身有焦點時；篩選框裡的 Enter（包含輸入法選字的 Enter）MUST NOT 接續或匯入；
- `m` 合併、`e` 改標頭、`d` 刪除、`p` pull、`P` push；
- 篩選框開著時，Esc 清掉篩選、收起篩選框，焦點回到清單。

焦點在預覽區時，按鍵 MUST 是「預覽區的游標與捲動」與「預覽區搜尋」規定的那些。清單的鍵（包含 ctrl+t）MUST NOT 在預覽區生效；預覽區的鍵也 MUST NOT 在清單生效。預覽區的 Esc MUST NOT 動到清單的篩選。

有視窗開著時（確認、選擇、輸入、結果、等待）：
- `Tab`、`shift+tab` MUST 只在那個視窗裡移動焦點（確認視窗：Tab 往下、shift+tab 往上），或什麼都不做；
- MUST NOT 改變底下畫面的焦點或分頁；
- 等待視窗裡 Esc 中斷，其他視窗裡 Esc 取消，照舊。

按鍵列 MUST 只顯示目前能用的鍵，依「分頁 × 哪一邊」而不同。焦點因任何原因改變（按鍵、滑鼠、打開篩選框或搜尋框）時，按鍵列 MUST 跟著換。

#### Scenario: 未匯入頁的按鍵列
- **WHEN** 在未匯入頁、焦點在清單
- **THEN** 按鍵列沒有 `m`、`e`、`d`、`P`

#### Scenario: Tab 切焦點、[ ] 換頁
- **WHEN** 焦點在清單，按 `Tab`
- **THEN** 焦點移到預覽區，頁面不變；再按 `]`，什麼都不發生；再按 `Tab` 回到清單，按 `]` 才換到下一頁

#### Scenario: 篩選框裡的 Enter
- **WHEN** 焦點在篩選框，打字後按 Enter
- **THEN** 篩選框收起來、篩選生效、焦點回到清單；不會開接續或匯入

#### Scenario: 從篩選框按 Tab
- **WHEN** 焦點在篩選框且已經打了字，按 `Tab`
- **THEN** 焦點移到預覽區，篩選框收起來，清單仍照那個字篩選

#### Scenario: 預覽區按清單的鍵
- **WHEN** 焦點在預覽區，按 `d`、`ctrl+t`
- **THEN** 不會開刪除的確認視窗，也不會切換標題與內文

#### Scenario: 確認視窗裡的 Tab
- **WHEN** 確認視窗開著，按 `Tab`，再按 `shift+tab`
- **THEN** 焦點在視窗裡往下、再往上；底下的清單與預覽區的焦點、分頁都沒有變

#### Scenario: 預覽區的 Esc 不動篩選
- **WHEN** 清單有篩選，焦點在預覽區且有搜尋標亮，按 Esc
- **THEN** 標亮清掉；清單的篩選還在，焦點仍在預覽區

### Requirement: 輸入法
互動模式 MUST 能在篩選框（與預覽區的搜尋框）用中文等輸入法打字、選字。選字時按的 Enter MUST NOT 讓剛選好的字消失。

為了做到這一點，互動模式啟動時 MUST 不啟用 kitty keyboard protocol：載入 Textual 之前，若環境變數 `TEXTUAL_DISABLE_KITTY_KEY` 沒有設定，就設成 `1`；已經設定時（不論值是什麼）MUST 照使用者的設定。指令模式不受影響。

#### Scenario: 預設關掉 kitty 鍵盤協定
- **WHEN** 環境變數裡沒有 `TEXTUAL_DISABLE_KITTY_KEY`，執行 `agora` 進入互動模式
- **THEN** Textual 不啟用 kitty keyboard protocol（`textual.constants.DISABLE_KITTY_KEY` 為真）

#### Scenario: 尊重使用者的設定
- **WHEN** 使用者設了 `TEXTUAL_DISABLE_KITTY_KEY=0` 再執行 `agora`
- **THEN** 照他的設定，啟用 kitty keyboard protocol

#### Scenario: 用輸入法選字
- **WHEN** 在 herdr 的 pane 裡打開 `agora`，按 `/`，用中文輸入法打「表格」並選字
- **THEN** 篩選框裡是「表格」，選字用的 Enter 沒有讓字消失

### Requirement: 預覽區的游標與捲動
預覽區 MUST 以唯讀方式顯示原始的 Markdown，並加上語法上色。`## user`、`## assistant` 這兩種標題行 MUST 用兩種不同的顏色，而且不和清單裡已有意義的顏色（各 agent、合併、標記、錯誤）重複。

預覽區 MUST 有游標。預覽區有焦點時，游標所在的那一行（原文的一行）整行高亮；焦點在清單時不高亮。

焦點在預覽區時：
- `j`、`↓` 往下，`k`、`↑` 往上：一次移動畫面上的一列，長段落折行時，會在同一個原文行裡移動；
- PgUp、PgDn 翻一頁，←、→、Home、End 在行內移動；
- 選取與複製照唯讀文字框的預設；
- `g` 到最前面，MUST 先把還沒載入的部分全部載入；
- `G` 到最後一行。

載入前一段（T6）的觸發條件：
- 游標在已載入內容的第一行又往上（`k`、`↑`、PgUp）；
- 或者捲到頂（滑鼠滾輪、捲軸）。

補上前一段之後，畫面 MUST NOT 跳到別處：
- 捲到頂觸發時（游標沒動）：原本最上面那一行在畫面上的位置 MUST 完全不變；
- 用 `k`、`↑`、PgUp 觸發時：游標移到前一段的最後，畫面只捲到讓游標看得到為止。原本那一行最多往下移一頁；用 `k`、`↑` 時剛好一列。

平常 MUST 只讀、只排檔案的尾端一段（T6）。只有 `g`、以及跳到還沒載入的搜尋符合時，才一次載入到需要的地方：這是使用者明確要求的例外。

換到另一個 Session 時，游標 MUST 在最後一行。

「↑ 往上捲…」提示 MUST 提到也可以按 `k`、`g` 載入。

#### Scenario: 游標移動
- **WHEN** 預覽的內容都是不會折行的短行，焦點在預覽區，按 `k` 三次
- **THEN** 游標在倒數第四行，該行整行高亮

#### Scenario: 按 k 補前一段不跳
- **WHEN** 游標在已載入內容的第一行，該行在預覽區的第 1 列，按 `k`
- **THEN** 前一段補在上面；游標在它的上一列，原本那一行移到第 2 列

#### Scenario: 捲到頂補前一段不跳
- **WHEN** 用滑鼠滾輪捲到已載入內容的頂端
- **THEN** 前一段補在上面；原本最上面那一行仍在第 1 列，游標不動

#### Scenario: 以 code block 結尾
- **WHEN** 最後一則以收尾的 ```` ``` ```` 結束，選到這一列
- **THEN** 預覽正常顯示，互動模式不會掛掉

#### Scenario: 到最前面
- **WHEN** 一個還有更早內容沒載入的大 Session，在預覽區按 `g`
- **THEN** 全部載入，游標在第一行，「↑ 往上捲…」提示消失

### Requirement: 預覽區搜尋
焦點在預覽區時，`/` MUST 在預覽區下方打開搜尋框。搜尋框裡的字母鍵是打字，不是快捷鍵。

輸入文字並按 Enter 後：
- MUST 找出**整份 Session**（包含還沒載入的部分）裡所有符合；
  - 不分大小寫；
  - 只比對對話內文，檔頭（front matter）不算；
- 游標 MUST 跳到從游標位置往下最近的符合；往下沒有時，MUST 跳到往上最近的那一個，不繞回最前面（預覽一打開游標在最後一行，使用者要的通常是離尾端最近的那一個，也不必為了它載入整份）；
- 已載入的符合 MUST 全部標亮；目前那一個 MUST 被選取；
- MUST 顯示「第 k 個／共 N 個」；
- 搜尋框關掉，焦點回到預覽區。

之後：
- `n` MUST 從游標的位置往下跳到下一個，`N` MUST 往上跳到上一個，到頭時繞回另一端；
- 要跳到的符合還沒載入時，MUST 先一次載入到包含它的那一段，再跳過去；
- 用 `j`、`k` 移動之後，選取消失，其他標亮保留；
- Esc：搜尋框開著時關掉搜尋框；沒開時清掉標亮與計數，游標留在原地。

找不到時 MUST 說「找不到」，游標不動。

搜尋狀態的生命週期：
- 換到另一個 Session 時，MUST 清掉搜尋框、標亮與計數。
  - 「同一個 Session」以清單那一列的 key 判斷；重讀之後那一列不在了（例如被刪掉），當成換到另一個 Session。
- 有搜尋時，同一個 Session 的預覽被換掉：
  - MUST 用同一個字重新搜，游標回到最後一行；
  - 未匯入頁從「最後一則」換成整份時，提示「已換成整份對話」；
  - 動作完成後重讀時，提示「內容已更新」。
- 沒有搜尋時，預覽被換掉不需要提示。
- 預覽只有最後一則時，計數 MUST 加上「（只有最後一則）」。
- 整份讀取失敗時，畫面 MUST NOT 一直停在「載入中」。

#### Scenario: 找到並跳過去
- **WHEN** 焦點在預覽區，按 `/`，打 `表格`，按 Enter
- **THEN** 游標跳到下一個「表格」，已載入的「表格」都標亮，顯示「第 k 個／共 N 個」

#### Scenario: 第一次搜尋找離尾端最近的
- **WHEN** 剛打開預覽（游標在最後一行），搜尋的字在已載入的尾端出現一次、在還沒載入的最前面也出現一次，按 Enter 送出
- **THEN** 游標跳到尾端那一個，前面不載入；顯示「第 2 個／共 2 個」

#### Scenario: 跳到還沒載入的地方
- **WHEN** 一個 2 MB 的 Session 只載入了最後一段，搜尋的字只出現在最前面，按 Enter 送出
- **THEN** 一次載入到包含它的那一段，游標跳到那裡，畫面上看得到它

#### Scenario: 檔頭不算
- **WHEN** 搜尋的字只出現在 `session.md` 的檔頭
- **THEN** 說「找不到」

#### Scenario: 清掉標亮
- **WHEN** 搜尋框沒開、有搜尋標亮時按 Esc
- **THEN** 標亮與計數消失，游標不動，焦點仍在預覽區

#### Scenario: 換 Session
- **WHEN** 有搜尋標亮時，在清單換到另一個 Session
- **THEN** 新的預覽沒有標亮，也沒有計數
